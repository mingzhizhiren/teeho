# 题火社区版 JSON 定制示例

本示例是教学实现，包含 JSON 数据源、完整六维算法和“示例收藏增长”展示项，不代表官方评分效果。Agent 必须配置；完整应用使用 Supabase 云项目，不需要 Docker。

## 开发运行

1. 在题火仓库根目录执行 `bun install`。
2. 按服务端环境示例配置自己的 Supabase 云项目和 Agent。社区版使用六维平均主分，不需要私有模型包。
3. 服务端从 server 工作目录启动时，设置 `TEEHO_PLUGIN_CONFIG=../plugins/example/config.ts`。
4. 运行 `bun run dev:server` 与 `bun run dev:frontend`，在网页提交完整笔记及必需素材；或让 Skill 的服务地址指向该实例。

数据文件采用固定合成观察时点。默认样本是“通勤防晒”，正文为“记录通勤防晒的具体场景与使用步骤。”。正式演示前把 JSON 发布时间、两次观察时间更新为真实有序且接近演示时间的合成日期，保持至少两次观察；宿主不会为过期证据伪造当前时点或绕过案例门槛。

## 替换数据来源

复制示例目录并更改插件与能力身份。在 source 中替换 `read`，用数据库查询返回同一 JSON 事实格式；只负责数据获取和整合，不操作用户任务或积分。数据包括笔记身份、标题、正文、话题、发布时间和实际互动观察。一次观察不能算增长，缺失用 null 表达，零是实际计数。

如需扩展字段，在数据源的 `extensions` 中声明命名空间与 schema，并在返回数据的 `extensions` 中提供对应值。例如，来源声明 `'my/price': z.number().nullable()`；消费它的指标声明 `requiresFacts: ['my/price']`，在 `compute` 中通过 `fact('my/price')` 读取。`fact` 返回 `unknown`，指标用相同 schema 收窄类型。宿主不会把整份扩展字段暴露给指标。

启动时会沿所选算法和展示指标的依赖链检查扩展字段能力；没有声明就拒绝启动。字段能力已声明但本次值缺失时，由 schema 明确允许 `null` 或 `undefined`，指标据此返回 `unavailable`。这与数据源根本没有提供该能力是两种情况。

数据源收到的任务是只读副本，指标收到的任务和证据也被冻结；需要整理内容时创建新对象。笔记和话题观察不得晚于传入的 `asOf`，话题的前次观察必须早于本次观察。抛错、非法数据或越过时间边界都会使任务失败；话题源明确返回 `failed` 或 `no_sources` 时，仍按现有话题不可用规则生成报告。服务端记录安全的能力身份和错误类别，不记录来源的原始异常详情。

素材理解后，任务的 `fields.track.value` 是主赛道身份，`secondaryTracks` 是最多三个次赛道的数字编码。JSON 笔记可以用 `trackCodes: [1, 3]` 声明所属赛道；省略时沿用单赛道示例行为，作为主赛道候选。只选择一个主赛道时取样占比为 100%；有次赛道时主赛道占 60%，其余 40% 由实际次赛道均分。适配器保留赛道归属、按笔记身份去重，并把缺额按剩余赛道权重补足。自行编写数据库适配器时也应遵守这个规则，返回入选笔记的历史观察；权重不直接乘到评分上。

指标只能使用统一事实或声明依赖的指标，不能直接查询数据库。不要将密码写入插件；在受控数据源中使用部署环境配置。

## 替换算法或增加展示指标

metrics 声明数据指标的类型、单位、口径、依赖和计算；algorithms 声明固定雷达维度与必需指标。指标之间通过 `requires` 声明依赖，再通过 `metric(id)` 读取。配置中每维选择一个已安装实现。可只替换一维，不增删维度，也不能改变现有维度的含义或范围。

每个指标必须声明 `kind`：

| 类型        | 适用场景                                     | 计算结果要求                               |
| ----------- | -------------------------------------------- | ------------------------------------------ |
| `feature`   | 单份内容的特征或原始字段，例如示例的内容形状 | 返回值或不可用原因，不填写统计依据         |
| `statistic` | 同类样本分布、增长等统计，例如示例收藏增长   | 额外返回 `basis`，包含实际样本数和时间窗口 |

统计结果示例：

```ts
return {
    status: 'available',
    value: averageGrowth,
    basis: {
        sampleCount: growthSamples.length,
        window: { kind: 'observations', start: firstObservation, end: lastObservation },
    },
}
```

`window.kind` 的 `observations` 表示实际观察范围；`analysis` 表示取样所用分析窗口。开始时间不能晚于结束时间，结束时间不得超过任务截止。无样本时可以返回 `basis: { sampleCount: 0, window: null }` 和 `unavailable`；如果已有实际查询窗口，也可保留该窗口。可用统计必须提供窗口。存在独立子样本时，在 `basis.cohorts` 中分别记录各组的 `sampleCount` 与 `window`，不能混用一个总体样本数。例如官方正文特征和图片几何各自保留统计依据。

宿主把统计依据与单位、指标版本、数据源版本、证据版本及截止时间绑定为 `metric(id).metadata`，提供给后续指标和算法，并保存到任务执行记录。特征类指标的样本数与窗口为 `null`。这些内部依据不会自动成为页面上的自定义展示项。

在 displayMetrics 中列出需要公开的指标身份、名称和可选说明，数组顺序即展示顺序。名称和说明按原文保存，不翻译；值仅支持有限数值或简短文本。未选中的内部指标不显示。证据不足返回 unavailable；异常或非法输出导致任务失败，不会自动切换其他算法。

通过 `bun run --cwd server test src/customization` 验证示例与契约，测试仅使用合成数据与 Agent 替身。实际使用仍需自己的 Agent 和云项目。

## 构建与分发

- 社区构建：`bun run --cwd server build`，生成宿主与示例配置包。
- 运行构建产物时从 server 目录设置 `TEEHO_PLUGIN_CONFIG=./dist/plugins/example/config.js`。
- 外部依赖包可由部署配置直接 import 并组合相同契约；宿主只加载受信任部署者提供的配置模块，不接收请求参数指定模块。

社区版不分发官方插件、正式模型权重或爬取数据。案例筛选采用截止时点前的最新实测互动总量排序，仅用于教学参考；不使用私有训练标签或官方调整权重。版本升级后的插件维护由开发者自行负责，不提供旧接口转换层、热更新或多语言沙箱。
